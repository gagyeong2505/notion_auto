# notion-db-analyze

트리거 키워드를 쓰지 않은 조회·분석 요청을 처리합니다.

> **이 스킬은 Notion에 절대 쓰지 않습니다**(페이지·데이터베이스 생성, 수정, 삭제 모두 금지).

## 입력

- `키워드:` 접두어가 없는 일반 요청.

## 처리 절차

1. **요청을 조회 조건으로 바꾸기**
   - `docs/notion-schema.md`의 매핑 기준으로 요청 표현을 필터 조건으로 바꿉니다.
     - 예: "오늘 마감" → 날짜 = 오늘, "지연" → 날짜 < 오늘 이고 상태 ≠ 완료, "미완료" → 상태 ≠ 완료.
   - 상대 날짜는 절대 날짜로 바꿉니다(Asia/Seoul, `YYYY-MM-DD(요일)`).
   - 대상 DB나 조건이 모호하면 조회하기 전에 사용자에게 묻습니다.

2. **`notion-analyst` 서브에이전트로 조회**
   - 요청 원문과 변환한 조건(날짜, 상태, 담당자 등)을 넘깁니다.

3. **보고**
   - `templates/report.md` 형식으로 적용한 조건, 조건에 맞는 항목 수, 항목 목록(제목, 날짜, 상태, 담당자, 링크)을 보여줍니다.

4. **후속 작업 제안**
   - `notion-analyst`가 돌려준 후속 작업 후보를 바탕으로 후속 작업(예: 마감 알림 메일 초안, 요약 문서 생성, 일정 등록)을 제안합니다.
   - 사용자가 승인한 경우에만 `gws-execute` 스킬로 넘깁니다.
   - 승인하지 않으면 추가 작업 없이 끝냅니다.

## 규칙

- 이 스킬에서는 Notion에 쓰지 않습니다. 분석 중 사용자가 데이터 수정을 요청하면, 승인이 필요한 별도의 등록·수정 흐름이 필요하다고 안내합니다.
- `docs/notion-schema.md`에서 확인한 속성 이름만 사용합니다.
- 승인 없이 후속 작업을 실행하지 않습니다.
