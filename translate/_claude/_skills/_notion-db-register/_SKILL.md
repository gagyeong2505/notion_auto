# notion-db-register

트리거 키워드로 정해진 대상 DB에 항목을 등록합니다.

> **사용자 승인 없이는 절대 등록하지 않습니다.**

## 입력

- 트리거 키워드와 첫 번째 콜론 뒤의 내용(`키워드: 내용`).
- 메인 세션이 해당 규칙 파일(`CLAUDE.md` 3번, `.claude/rules/`)로 정한 대상 DB. 트리거 DB보다 우선합니다.
- 키워드가 트리거 DB에 있으면 그 정보: 기본값과 후속 작업(대상 DB는 규칙 파일이 없는 키워드일 때만 사용).

## 처리 절차

1. **대상 DB 속성 구조 확인**
   - `docs/notion-schema.md`에서 대상 DB의 속성 이름과 타입을 확인합니다. 이 파일이 없으면 `notion-fetch`로 대상 DB를 조회해 실제 속성 이름을 사용합니다.
   - 추측한 속성 이름은 절대 사용하지 않습니다.

2. **입력을 속성에 맞게 나누기**
   - 입력 내용을 대상 DB의 속성(예: 제목, 날짜, 장소, 메모)에 맞춰 나눕니다.
   - 날짜·시간 표현("내일", "다음 주 월요일", "3시" 등)은 Asia/Seoul 시간대 기준으로 `YYYY-MM-DD(요일)` / `HH:mm` 형식의 절대값으로 바꿉니다.
   - 필수 속성을 정할 수 없으면 추측하지 말고 사용자에게 묻습니다.

3. **트리거 DB 기본값 적용**
   - 트리거 DB에 정의된 기본값(예: 상태 = 예정)을 채웁니다.
   - 사용자가 직접 준 값이 기본값보다 우선합니다.

4. **미리보기를 보여주고 승인 요청**
   - `templates/register-preview.md` 형식(템플릿이 없으면 일반 목록)으로 대상 DB, 각 속성 값, 적용한 기본값, 예정된 후속 작업을 보여줍니다.
   - 사용자의 응답을 기다립니다.
     - **승인** → 5단계로 진행합니다.
     - **수정 요청** → 고친 뒤 미리보기를 다시 보여줍니다.
     - **거절 / 응답 없음** → 중단합니다. 등록하지 않습니다.

5. **`notion-writer` 서브에이전트로 등록**
   - 승인된 속성 값, 대상 DB, 사용자가 승인했다는 사실을 넘깁니다.
   - 등록 결과(제목, 대상 DB, 페이지 링크)를 받아 사용자에게 보고합니다.
   - `CLAUDE.md` 3.1로 분류된 메모는 `저장됨: [DB명]` 한 줄만 보고합니다.

6. **후속 작업 위임**
   - 트리거 DB에 후속 작업(메일, 파일, 일정)이 지정되어 있으면 `notion-writer`가 돌려준 정보와 함께 `gws-execute` 스킬로 넘깁니다.
   - 후속 작업이 없으면 여기서 끝냅니다.

7. **기록**
   - 결과를 `logs/actions.md`에 기록합니다.

## 규칙

- 승인 없이 등록하지 않습니다.
- 이 스킬에서 Notion에 직접 쓰지 않습니다. 항상 `notion-writer` 서브에이전트를 사용합니다.
- 등록이 실패하거나 일부만 성공하면 성공한 항목과 실패한 항목을 원인과 함께 나눠 보고합니다.
